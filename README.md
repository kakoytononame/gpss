# GPSS Studio Web

Веб-версия GPSS Studio состоит из React + TypeScript frontend, ASP.NET Core + EF Core backend и PostgreSQL. Для переноса и запуска все компоненты упакованы в Docker Compose.

## Запуск из готовых образов (без сборки)

Готовые образы собираются GitHub Actions (`.github/workflows/docker.yml`) при каждом push и публикуются в GitHub Container Registry: `ghcr.io/kakoytononame/gpss-api` и `ghcr.io/kakoytononame/gpss-web`. Вместе с ними собирается архив `GPSS-Studio-<версия>.zip`: кнопки `START_GPSS_STUDIO.cmd` / `STOP_GPSS_STUDIO.cmd` и `docker-compose.yml` с этими образами, без исходного кода.

1. Установите Docker Desktop (один раз).
2. Скачайте архив: вкладка Actions → последний запуск «Docker images» → Artifacts (или раздел Releases для версий `v*`).
3. Распакуйте и дважды щёлкните `START_GPSS_STUDIO.cmd`: образы скачиваются (первый раз около 500 МБ), приложение открывается в браузере. На компьютере ничего не собирается.

Если при скачивании образов Docker пишет `denied` или `unauthorized`, образы ещё не открыты для всех: на GitHub откройте профиль → Packages → `gpss-api` и `gpss-web` → Package settings → Change visibility → Public (один раз).

Новая версия: `git tag v1.0.0 && git push origin v1.0.0` — образы получат теги `1.0.0` и `latest`, архив прикрепится к релизу.

## Запуск одной кнопкой на Windows (сборка из исходников)

На новом ноутбуке один раз установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) с поддержкой WSL 2. Node.js, .NET SDK и PostgreSQL отдельно устанавливать не нужно.

1. Скопируйте и распакуйте папку проекта.
2. Запустите `START_GPSS_STUDIO.cmd` двойным щелчком.
3. Дождитесь сборки. При первом запуске Docker загрузит базовые образы, поэтому потребуется интернет и несколько минут.
4. После проверки сервисов браузер автоматически откроет `http://127.0.0.1:8080`.

Лаунчер выполняет следующие действия:

- проверяет наличие Docker и Docker Compose;
- при необходимости запускает Docker Desktop и ожидает его готовности;
- собирает и запускает frontend, backend и PostgreSQL;
- проверяет API, соединение с базой данных и веб-интерфейс;
- открывает приложение в браузере только после успешного запуска.

Для остановки используйте `STOP_GPSS_STUDIO.cmd`. Контейнеры будут остановлены, но данные PostgreSQL сохранятся в Docker volume.

## Подготовка архива для переноса

Запустите `CREATE_TRANSFER_PACKAGE.cmd`. В папке `artifacts` появится архив `GPSS-Studio-portable-ДАТА-ВРЕМЯ.zip` без локальных зависимостей, Git-истории, логов и результатов сборки.

Архив содержит исходный код, Docker-конфигурацию и кнопки запуска. Его можно перенести на другой Windows-компьютер, распаковать и запустить через `START_GPSS_STUDIO.cmd`.

## Адреса сервисов

- веб-интерфейс: `http://127.0.0.1:8080`;
- backend API: `http://127.0.0.1:3001/api/health`;
- PostgreSQL: `127.0.0.1:55432`;
- база данных: `gpss`;
- пользователь: `gpss`;
- пароль: `gpss`.

Порты `8080`, `3001` и `55432` должны быть свободны. Если запуск завершился ошибкой, окно не закроется и покажет последние сообщения контейнеров.

При необходимости внешний порт PostgreSQL можно изменить перед запуском, задав переменную окружения `GPSS_DB_PORT`. Внутри Docker backend всегда подключается к базе на стандартном порту `5432`.

## Моделирование GPSS

Сервер содержит собственный интерпретатор GPSS World (`backend/GpssStudio.Simulation`): транслятор модели, цепи текущих и будущих событий, генераторы случайных чисел (потоки RN1…RNn, воспроизводимые), стандартный отчёт и данные для графиков.

Как пользоваться:

1. Откройте документ «Текст модели». При первом запуске в него загружается пример «Столовая» (5 касс, 5 раздач, зал на 300 мест, 20 столиков, сутки работы).
2. «Проверить» — трансляция без запуска; ошибки с номерами строк попадают в панель «Замечания и ошибки».
3. «Запустить моделирование» (панель быстрого доступа, лента, схема или документ «Текст модели») — модель транслируется и выполняются её управляющие операторы (`START` и др.; если `START` нет, выполняется `START 1`). После завершения открывается «Стандартный отчёт».
4. «Графики результатов» (дерево проекта или кнопка «Показать графики таблиц» на вкладке отчёта): загрузка устройств, длины и времена очередей, динамика очередей и памяти во времени, гистограммы таблиц, входы в блоки.
5. «Журнал моделирования» — журнал и командная строка GPSS: `START n`, `STEP n` (пошаговое выполнение с трассировкой), `HALT`, `CONTINUE`, `RESET`, `CLEAR`, `SHOW выражение`, `INITIAL`, `RMULT`, `STOP`. Те же команды доступны на вкладке ленты «Моделирование».
6. Редактор текста модели подсвечивает синтаксис, показывает таблицу имён, переходит к определению имени (F12) и к строке с ошибкой. Щелчок по номеру строки ставит точку останова: моделирование останавливается перед входом в блок, документ «Состояние модели» показывает цепи событий, транзакты и их параметры, «STEP» и «CONTINUE» продолжают выполнение.
7. «Стандартный отчёт» можно править, копировать и выгружать в CSV для Excel.
8. «Эксперименты» (лента «Моделирование → Эксперименты») — серия прогонов по полному факторному плану: факторы `X$`, ёмкость памяти, константа `EQU` или операнд строки модели; несколько прогонов в точке с разными случайными числами, средние и 95 % доверительные интервалы показателей, лучшая точка по целевому показателю, графики и выгрузка в CSV.

Поддерживаемые блоки: `GENERATE, TERMINATE, ADVANCE, SEIZE, RELEASE, PREEMPT, RETURN, FAVAIL, FUNAVAIL, QUEUE, DEPART, ENTER, LEAVE, SAVAIL, SUNAVAIL, TRANSFER` (безусловный, вероятностный, `BOTH`, `ALL`, `PICK`, `SBR`, `P`, `FN`), `TEST, GATE, LOGIC, SAVEVALUE, MSAVEVALUE, ASSIGN, MARK, PRIORITY, SPLIT, ASSEMBLE, GATHER, MATCH, LOOP, BUFFER, TABULATE, LINK, UNLINK, ADOPT, INDEX, COUNT, SELECT, DISPLACE, JOIN, REMOVE, EXAMINE, SCAN, ALTER, PLUS, EXECUTE, TRACE, UNTRACE`, а также `OPEN, READ, WRITE, SEEK, CLOSE` (файлы хранятся в памяти сеанса).

Операторы: `STORAGE, TABLE, QTABLE, VARIABLE, FVARIABLE, BVARIABLE, FUNCTION` (D, C, L, E; точки могут быть выражениями), `MATRIX, EQU, INITIAL` (в т. ч. `MX$`), `START, RESET, CLEAR, SHOW, RMULT`. Выражения вычисляются с приоритетами операций GPSS World (`^`; `# * / \`; `@`; `+ -`; сравнения; `= !=`; `&`/`'AND'`; `|`/`'OR'`), поддерживают СЧА (`Q$, QA$, QM$, QT$, F$, FC$, FR$, S$, R$, SR$, X$, MX$(m,n), P$/Pn, FN$, V$, BV$, N$, W$, LS$, TB$, CH$, CA$, CT$, GN$, GT$, MB$, RNn, AC1, C1, M1, XN1, PR, TG1` и др.), косвенную адресацию (`Q*Param`, `*Param`) и процедуры `Exponential, Uniform, Normal, Triangular, Poisson, Duniform, Lognormal, Gamma, Weibull`, а также математические функции. Объекты адресуются номерами: имя, его номер из `EQU` и число в параметре транзакта указывают на один и тот же объект, как в GPSS World.

PLUS-процедуры (`PROCEDURE`) выполняются: `TEMPORARY`, присваивание (глобальные переменные пользователя доступны всей модели), `BEGIN/END`, `IF/THEN/ELSE`, `WHILE/DO`, `GOTO` с метками операторов, `RETURN`, рекурсивные вызовы; процедуру можно вызывать из любого выражения, в том числе в операндах блоков. Не поддерживаются `TEMPORARY MATRIX`, PLUS-эксперименты (`EXPERIMENT`/`CONDUCT`), непрерывные переменные (`INTEGRATE`) и `INCLUDE`; транслятор сообщает об этом. Бесконечные циклы и накопление транзактов останавливаются защитными пределами с сообщением в журнале.

## Конструктор систем массового обслуживания

Лента «Моделирование → СМО → Конструктор СМО» открывает документ, в котором система массового обслуживания или сеть описывается без программирования, моделируется на GPSS и сравнивается с теорией массового обслуживания.

- **Классы заявок:** открытый поток (интервал — экспоненциальный M, постоянный D, Эрланга Ek, гиперэкспоненциальный H2, равномерный U, нормальный N, логнормальный LN, треугольный T, гамма Γ, Вейбулла W; групповые поступления фиксированного, равномерного или геометрического размера) или замкнутый класс с конечным числом заявок и временем вне системы (модель наладчиков, Энгсета, замкнутые сети). Приоритет класса, своё время обслуживания в отдельных узлах.
- **Узлы:** число каналов (в том числе неограниченное — M/G/∞), ёмкость (система с отказами, ограниченная очередь), дисциплина FIFO, LIFO, случайный выбор (SIRO), кратчайшая работа первой (SPT), относительный и абсолютный приоритет (с дообслуживанием прерванной заявки), циклическое обслуживание с квантом (≈ разделение процессора).
- **Поведение заявок и приборов:** отказ от вступления в очередь (вероятность 1 − w/порог или 1/(w + 1)), уход из очереди по истечении терпения, повторные попытки с орбиты, отпуска прибора, отказы и восстановление.
- **Сети:** переходы между узлами с вероятностями (последовательные фазы, обратные связи, открытые и замкнутые сети).
- **Теория** пересчитывается после каждого изменения: точные решения — процессы гибели и размножения (M/M/c/K, Эрланг A и B, конечный источник, отказ от очереди), Эрланг C, Полячек–Хинчин (в том числе с отпусками, групповыми поступлениями, SPT, приоритетами Кобхэма и с прерыванием), GI/M/1, M/G/1/K, M/G/1 с повторными вызовами, M/G/∞, сети Джексона, точный анализ средних значений (MVA) замкнутых сетей с многоканальными станциями; приближения Кингмана и Аллена–Каннена с декомпозицией сети (QNA). Для каждого узла показаны обозначение Кендалла, метод и пометка «точное решение», «приближение» или «только моделирование».
- **«Моделировать и сравнить»** выполняет несколько независимых прогонов модели GPSS (разгон и RESET, затем сбор статистики) и показывает рядом с теорией средние значения с 95 % доверительными интервалами и отклонение (✓ — теория внутри интервала).
- **«Анализ результатов»** находит узкие места, потери, неточные оценки и советует, что изменить (например, сколько каналов нужно для загрузки 80 %). Если на сервере подключена языковая модель — локальная (Ollama, профиль `ai`) или Claude по API, — она поясняет выводы; подробности в [AI_ANALYSIS.md](AI_ANALYSIS.md).
- **«Открыть текст модели GPSS»** открывает сформированную модель в документе «Текст модели»: её можно запускать, отлаживать и использовать в «Экспериментах». В каталоге 29 примеров (от M/M/1 до модели центрального сервера); каждый из них проверяется тестами — точные формулы должны совпасть с моделированием.

## Проекты GPSS Studio

Проекты хранятся на сервере (PostgreSQL) в формате, повторяющем структуру проекта GPSS Studio: модели, структурные схемы из ТЭБов (элементарных, композитных, ТЭБов с данными), связи между входами и выходами, библиотеки ТЭБов, текст модели.

1. «Главная → Открыть проект / Управление» открывает документ «Проекты».
2. «Импорт проекта GPSS Studio» принимает ZIP-архив папки проекта (с `Project.gsproj`, `SimModels/…/Diagram.gsdiagram`, `ModelText.gps`, `TebsLibraries/*.tlib`) или отдельный файл модели `.gps`/`.txt`. Имена файлов в архиве допускаются в UTF-8 и CP866.
3. Схема модели открывается в документе «Структурная схема»; двойной щелчок по композитному ТЭБу открывает его схему, строка навигации возвращает на верхние уровни, двойной щелчок по элементарному ТЭБу открывает его в «Редакторе ТЭБа» (изменения записываются в проект).
4. «Сгенерировать текст модели» (схема, лента «Моделирование → Схема» или документ «Проекты») собирает текст GPSS по правилам GPSS Studio: корректировка имён (`teb4_Метка`), области действия ТЭБов с данными, переходы по выходам (прямой/копии `SPLIT`, первый доступный, случайный, по модели связи), модели связей, переход через границы композитных ТЭБов, перенос `START` в конец. Ошибки и предупреждения генератора попадают в «Замечания и ошибки» с указанием ТЭБа.
5. Формы модели (папка `Forms` проекта GPSS Studio) появляются в дереве проекта. «Форма ввода данных» показывает макет формы и таблицу исходных данных: значения записываются в операнды строк текста формы («Сформировать модель»), «Моделировать» запускает модель с числом завершений и сбором динамики показателей из формы, «План эксперимента» переносит факторы и целевые показатели формы в «Эксперименты». «Динамическая форма» показывает поля СЧА с цветовыми интервалами, диаграммы и графики динамики показателей по ходу моделирования.
6. «Сохранить проект» записывает проект на сервер (вместе с исходными данными форм); открытый проект восстанавливается вместе с рабочей областью.
7. «Результаты моделирования» (узел дерева проекта) — база результатов проекта на сервере. Прогон по форме сохраняется как одиночный эксперимент (текст модели, исходные данные формы, стандартный отчёт, динамика показателей), серия из «Экспериментов» — вместе с планом, таблицей точек и графиками; обычный прогон сохраняется кнопкой «Сохранить прогон». Результаты можно переименовать и удалить; при удалении проекта удаляются и его результаты.
8. «Итоговый отчёт» (узел дерева проекта или кнопка в «Результатах моделирования») собирается из результатов: «Добавить в отчёт» на вкладке результата переносит её таблицы, текст модели и графики (картинками). В отчёт добавляются заголовки разделов и тексты выводов, фрагменты переставляются и удаляются. Отчёт хранится в проекте («Сохранить проект») и выгружается в HTML или в Word (`.doc` с рисунками).
9. «Тесты ТЭБов» (правая панель) проверяют каждый ТЭБ текущей модели, в том числе внутри композитных: заголовок и имя в модели (уникальность), GPSS-модель (или внутреннюю схему, объекты GPSS), значения параметров, связи входов и выходов по сообщениям генератора, а также генерацию и трансляцию всей модели. Результаты группируются по ТЭБам; щелчок по тесту открывает ТЭБ на структурной схеме. Без открытого проекта проверяется ТЭБ в редакторе.

Подробное сравнение с GPSS Studio — в [GPSS_STUDIO_PORT.md](GPSS_STUDIO_PORT.md).

## API

Swagger UI: `http://127.0.0.1:3001/swagger`.

- `GET/PATCH/PUT/POST/DELETE /api/alina-gpss/studio/tebs/...` — классы и экземпляры ТЭБов, параметры, коллекции, текст GPSS-модели;
- `GET/PUT/DELETE /api/alina-gpss/studio/tebs/workspace` — снимок рабочей области;
- `POST /api/alina-gpss/studio/simulation/translate` — трансляция модели;
- `POST /api/alina-gpss/studio/simulation/sessions` — создать сеанс моделирования (трансляция + управляющие операторы модели);
- `POST /api/alina-gpss/studio/simulation/sessions/{id}/commands` — команда GPSS в сеансе;
- `POST /api/alina-gpss/studio/simulation/sessions/{id}/evaluate` — значения выражений (СЧА) в текущем состоянии сеанса; при создании сеанса можно передать `BreakpointLines`, `Monitors` и `MonitorInterval` (сбор динамики показателей);
- `POST /api/alina-gpss/studio/experiments` — серия экспериментов по плану;
- `GET /api/alina-gpss/studio/simulation/examples/{id}` — примеры моделей;
- `GET/POST /api/alina-gpss/studio/projects`, `GET/PUT/DELETE /api/alina-gpss/studio/projects/{id}` — проекты;
- `POST /api/alina-gpss/studio/projects/import` — импорт проекта GPSS Studio (multipart, поле `file`: ZIP, `.gps`, `.txt`, до 25 МБ);
- `POST /api/alina-gpss/studio/projects/{id}/models/{n}/generate`, `POST /api/alina-gpss/studio/projects/generate` — генерация текста модели по сохранённой или переданной схеме;
- `POST /api/alina-gpss/studio/projects/forms/apply` — запись исходных данных формы в её текст модели;
- `GET /api/alina-gpss/studio/results?projectId=…`, `POST /api/alina-gpss/studio/results`, `GET/PATCH/DELETE /api/alina-gpss/studio/results/{id}` — результаты моделирования проекта (одиночные эксперименты и серии);
- `GET /api/alina-gpss/studio/queueing/presets`, `POST /api/alina-gpss/studio/queueing/{validate|generate|analyze|simulate}` — конструктор СМО: каталог систем, проверка описания, текст модели GPSS, теория массового обслуживания, прогоны с доверительными интервалами;
- `GET /api/alina-gpss/studio/analysis/status`, `POST /api/alina-gpss/studio/analysis/queueing` — анализ результатов: находки и рекомендации, пояснение языковой модели, если она подключена;
- `GET /api/health` — состояние API и соединения с PostgreSQL.

Ошибки возвращаются в формате RFC 7807 (`application/problem+json`): 400 для неверных данных, 404 для отсутствующих объектов.

## Тестирование

Всё запускается в Docker, локально ничего кроме Docker не требуется:

```powershell
docker compose --project-name gpss up --detach --build
docker compose --project-name gpss --profile test run --rm api-tests   # 162 теста симулятора и конструктора СМО + 37 тестов импорта, форм и генерации + 72 теста API
```

Проверка на примерах из дистрибутива GPSS Studio (примеры не входят в репозиторий, скрипт скачивает установщик с официального ресурса разработчика и распаковывает только примеры в `vendor/`):

```sh
scripts/fetch-gpss-studio-samples.sh
GPSS_STUDIO_SAMPLES=$PWD/vendor/gpss-studio-samples dotnet test backend/GpssStudio.Projects.Tests
```

Для каждого примера импортируется проект, по схеме генерируется текст модели, и результат моделирования сравнивается с текстом модели, сохранённым GPSS Studio (совпадает модельное время завершения); сохранённый текст модели завершается в момент, записанный в журнале GPSS World из примера; формы примеров читаются, заполняют свой текст модели, и модель выполняется.

## Структура проекта

- `src/app` — сборка приложения и композиция основной оболочки;
- `src/features/teb-editor` — модель данных, хранилище состояния (срезы Zustand) и документы редактора: ТЭБ, схема, текст модели, отчёт, журнал, графики;
- `src/widgets` — крупные панели интерфейса GPSS Studio (лента, дерево проекта, свойства, замечания);
- `src/shared` — общие типы, API-клиенты, компоненты и графические ресурсы;
- `backend/GpssStudio.Simulation` — интерпретатор GPSS: транслятор, блоки, движок, PLUS-процедуры, стандартный отчёт, эксперименты, примеры моделей; `Queueing/` — конструктор СМО (описание, генератор модели, теория, прогоны, каталог);
- `backend/GpssStudio.Projects` — форматы проектов GPSS Studio (импорт проектов и форм), генератор текста модели по структурной схеме, заполнение текста формы;
- `backend/GpssStudio.WebApi` — ASP.NET Core Web API, сервисы, EF Core, схема БД (создаётся при старте API);
- `backend/*.Tests` — тесты симулятора, импорта и генерации, интеграционные тесты API;
- `e2e` — сквозные тесты Playwright;
- `docker` — конфигурация nginx;
- `scripts/windows` — переносимый запуск и упаковка проекта;
- `scripts/fetch-gpss-studio-samples.sh` — загрузка примеров GPSS Studio для проверок;
- `docker-compose.yml` — frontend, backend, PostgreSQL и тестовые сервисы (профиль `test`).

## Хранение данных

PostgreSQL использует именованный Docker volume `gpss_postgres_data`. Обычная остановка или обновление контейнеров данные не удаляет. Не запускайте `docker compose down --volumes`, если требуется сохранить проекты и результаты моделирования.
