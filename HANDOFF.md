# Передача работы (перенос GPSS Studio)

## Что сделано

Подробная карта функций со статусами: [GPSS_STUDIO_PORT.md](GPSS_STUDIO_PORT.md). Кратко:

- Ядро GPSS World (`backend/GpssStudio.Simulation`): почти все блоки и команды, PLUS-процедуры, `TRANSFER FN`, матрицы, группы, потоки, точки останова (`STOP`), сбор динамики показателей (`Monitors`), вычисление СЧА в сеансе (`evaluate`), эксперименты (`ExperimentRunner`, в т. ч. факторы «операнд строки»).
- Проекты GPSS Studio (`backend/GpssStudio.Projects`): импорт `.gsproj`/`.gsdiagram`/`.gps`/`.tlib`/`Form.fog`, генератор текста модели по схеме, заполнение текста формы (`FormModelBuilder`).
- Web API (`backend/GpssStudio.WebApi`): ТЭБы, моделирование, проекты, формы (`projects/forms/apply`), эксперименты, **результаты** (`/api/alina-gpss/studio/results`: список по проекту, получение, создание, переименование, удаление; таблица `simulation_results`) — бэкенд результатов готов и покрыт тестами, фронтенда для него ещё нет.
- Фронтенд (`src/`): структурная схема с иерархией, редактор ТЭБа, текст модели (подсветка, F12, таблица имён, точки останова), «Состояние модели», отчёт (правка, CSV), графики, «Эксперименты», «Форма ввода данных», «Динамическая форма».
- Проверки на 6 примерах из дистрибутива (`scripts/fetch-gpss-studio-samples.sh`, `GPSS_STUDIO_SAMPLES=...`): генерация совпадает с текстами Studio, время завершения совпадает с журналами GPSS World, формы читаются и выполняются.
- Тесты: движок 98, проекты 37 (52 с примерами), API 62, Vitest 92, Playwright 12 — все зелёные.

## Что осталось

1. **Фронтенд «Результаты моделирования»** (руководство, гл. 13.5–13.8): тип/клиент для `/results`, срез состояния, документ с деревом «Одиночные эксперименты / Серии экспериментов», вкладки «Общая информация», «Текст модели», «Исходные данные», «Динамика показателей», «Стандартный отчёт»; для серий — таблица и графики. Автосохранение после `runForm` и `runExperiment`; переименование, удаление; узел «Результаты» в дереве проекта.
2. **Виртуальный (итоговый) отчёт**: «Добавить в отчёт» на вкладках результата, список фрагментов, выгрузка в HTML (открывается в Word), графики — PNG из SVG через canvas.
3. Тесты ТЭБов, связанные с проектом (сейчас панель тестов демонстрационная).
4. Анимационная форма, оптимизация IOSO (сейчас перебор по сетке), экспорт проекта обратно в формат GPSS Studio, `TEMPORARY MATRIX`, `EXPERIMENT/CONDUCT`, `INCLUDE`, `INTEGRATE`, подсказки и сворачивание строк в редакторе, управляющие комментарии отладчика.
5. Обновить README/GPSS_STUDIO_PORT.md и счётчики тестов после каждого пункта.

## Локальный ИИ-компонент аналитики (запрос пользователя, не начат)

Предлагаемый дизайн — лёгкий, на CPU, без внешних сервисов:

- **Слой 1 — детерминированная аналитика (C#, без модели):** сервис `ResultAnalyzer` в `GpssStudio.Simulation` по отчёту/серии находит узкие места (загрузка устройств/памяти > 0.85, рост очередей, тренд динамики, нестационарность — сравнение половин прогона), чувствительность показателей к факторам (регрессия по точкам серии), рекомендации по числу прогонов (по ширине доверительного интервала). Выдаёт структурированные «находки» с числами. Это работает всегда и быстро.
- **Слой 2 — локальная языковая модель (опционально):** профиль `ai` в `docker-compose.yml` с `llama.cpp server` (образ `ghcr.io/ggml-org/llama.cpp:server`, CPU) и маленькой квантованной моделью ~1–4 млрд параметров в GGUF Q4 (например, Qwen2.5-1.5B/3B-Instruct, которые понимают русский), модель скачивается скриптом в volume. API получает эндпоинт `POST /api/alina-gpss/studio/analysis` : собирает находки слоя 1 + сжатые таблицы отчёта и просит модель написать пояснение на русском (температура низкая, лимит токенов, таймаут). Если сервис модели недоступен — возвращаются только находки слоя 1.
- **Фронтенд:** документ «Аналитика» (или вкладка в отчёте/результатах): список находок с подсветкой объектов, кнопка «Пояснить» (ответ модели потоково), вопросы к результатам в свободной форме с контекстом текущего отчёта.
- Требования к ресурсам: 4 потока CPU и 3–4 ГБ ОЗУ для 3B-модели в Q4; ответ 10–30 с.
