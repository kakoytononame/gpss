# Перенос функций GPSS Studio

Веб-приложение повторяет возможности настольной среды GPSS Studio (Элина-Компьютер, версия 1.7.34, студенческая) и её ядра GPSS World. Код GPSS Studio не используется: форматы файлов проектов, правила генерации модели и поведение языка восстановлены по руководствам из дистрибутива, по файлам примеров и по результатам их моделирования, реализация написана заново.

Как проверялось (`backend/GpssStudio.Projects.Tests/SampleProjectTests.cs`, примеры загружает `scripts/fetch-gpss-studio-samples.sh`):

- шесть примеров проектов из дистрибутива (АЗС, Агропромпарк, Модель порта, Столовая, Строительство, Схема производства роботов) импортируются, по их схемам генерируется текст модели, и модель, собранная нашим генератором, моделируется с тем же результатом (модельное время завершения), что и текст, сохранённый самой GPSS Studio;
- сохранённые тексты моделей завершаются в тот же момент модельного времени, что записан в журнале GPSS World из дистрибутива (`StdJournal.sim`: АЗС — 61200, Модель порта — 12000, Столовая — 1440);
- формы всех примеров читаются, их исходные данные записываются в текст формы, модель транслируется и выполняется, все поля и диаграммы форм ссылаются на существующие объекты.

Обозначения: ✅ сделано, 🟡 частично, ⬜ ещё не сделано.

## Проекты и файлы

| Функция GPSS Studio | Статус | Как сделано |
| --- | --- | --- |
| Проект: модели, библиотеки ТЭБов, описание | ✅ | Документ проекта на сервере (PostgreSQL), документ «Проекты», дерево «Текущий проект» строится по открытому проекту |
| Открытие проекта GPSS Studio (`Project.gsproj`, `Diagram.gsdiagram`, `ModelText.gps`, `*.tlib`) | ✅ | Импорт ZIP-архива папки проекта; граф DataContract с `z:Id/z:Ref`, RTF-текст модели (кодовые страницы шрифтов, `\uN`), значения матриц в двоичном формате .NET читаются как данные |
| Создание, сохранение, удаление проектов | ✅ | `/api/alina-gpss/studio/projects` |
| Несколько моделей в проекте, текущая модель | ✅ | Переключение в дереве проекта и в документе «Проекты» |
| Экспорт проекта обратно в формат GPSS Studio | ⬜ | Есть преобразование текста в RTF (`RtfText.FromPlainText`), запись `.gsdiagram` не реализована |
| Пользовательские файлы с данными модели (`*.txt`) | 🟡 | Потоки данных `OPEN/READ/WRITE/SEEK/CLOSE` работают с файлами в памяти сеанса; загрузка файлов из проекта в сеанс не подключена |

## Генерация модели по схеме (раздел 3.15)

| Правило | Статус | Примечание |
| --- | --- | --- |
| Заголовок модели, комментарий `* ТЭБ «…»` для каждого ТЭБа, пустая строка после ТЭБа | ✅ |
| Корректировка имён: метки и локальные объекты получают префикс имени ТЭБа (`teb4_Pier1`), параметры транзактов не меняются | ✅ |
| Области действия данных: объекты ТЭБа данных видны на своём уровне и ниже, внутри композитного ТЭБа получают его префикс | ✅ |
| ТЭБ данных: `EQU`, `INITIAL X$`, `STORAGE`, `BVARIABLE/VARIABLE/FVARIABLE (…)`, `MATRIX` + `INITIAL MX$`, `INITIAL LS$`, `FUNCTION` | ✅ |
| Вход на первый блок: метка `tebN_autoGeneratedK_firstBlock` или существующая метка блока; вход по метке | ✅ |
| Выход «последний блок» и выход по метке; переход к адресату, удаление лишнего `TRANSFER`, если адресат следует сразу | ✅ |
| «Прямой переход или копирование» с несколькими соединениями: `* Выход №n`, `SPLIT 1,…` | ✅ |
| «Случайный переход»: цепочка `TRANSFER p,,…` (с учётом заданных вероятностей связей) | ✅ |
| «Переход по первому доступному соединению» | 🟡 | Цепочка `TRANSFER BOTH`; при отказе всех адресатов транзакт ждёт последние два, а не все |
| «Определяется моделью» и модели связей (отдельный фрагмент `connectionN_…`) | ✅ |
| Закрывающий `TERMINATE`, если транзакт мог бы перейти в следующий ТЭБ | ✅ |
| Перенос `START` и других команд в конец модели | ✅ |
| Параметры ТЭБа: подстановка значений | ✅ |
| Диагностика: ошибки, предупреждения, сообщения с указанием ТЭБа | ✅ | Панель «Замечания и ошибки»; дополнительно сгенерированный текст транслируется |
